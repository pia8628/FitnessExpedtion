## Context

目前 Streamlit UI 各頁面缺少操作說明與一致的遊戲名稱標識，玩家容易混淆流程。專案也缺少版本更新頁面與一致的版本號呈現，難以追蹤變更與測試狀態。現況 UI 分散於 `ui/` 模組，入口由 `app.py` 組裝。

## Goals / Non-Goals

**Goals:**
- 在各主要頁面加入簡短說明文字，改善可理解性。
- 在各頁面上方呈現統一遊戲名稱「活力遠征 Fitness Expedition」。
- 新增版本更新頁面，提供變更紀錄。
- 將版本號更新為 `0.1.1 beta`，並在 UI 顯示。

**Non-Goals:**
- 不改動核心遊戲規則或資料結構。
- 不新增外部依賴或資料庫。
- 不重構整體 UI 架構或導覽模式。

## Decisions

- **統一頁首呈現遊戲名稱與版本號**
  - 方案：在 `app.py` 或共用 UI helper 中建立 `render_header()`，所有頁面呼叫一次。
  - 理由：避免每頁重複字串，未來版本更新只改一處。
  - 替代方案：各頁自行寫死名稱與版本號。缺點是重複與維護成本高。

- **版本號來源集中化**
  - 方案：新增 `config/version.py` 或 `config/settings.py` 的 `APP_VERSION` 常數，UI 從此讀取。
  - 理由：明確單一來源，便於後續更新。
  - 替代方案：直接在 UI 寫死版本號，容易漏改。

- **版本更新頁內容先用靜態資料**
  - 方案：新增 `ui/changelog.py`（或 `ui/version.py`）以靜態列表呈現版本紀錄。
  - 理由：無需新資料表、快速落地。
  - 替代方案：改由 Google Sheet/外部檔案管理。需額外流程與欄位規劃，超出本次範圍。

- **頁面說明文字以「簡短提示」為主**
  - 方案：每頁 2–4 行，描述該頁目的與操作流程。
  - 理由：減少閱讀負擔，避免干擾主要操作。

## Risks / Trade-offs

- [說明文字過多導致版面壓迫] → 以短句、可折疊區塊或較小字級呈現。
- [版本更新頁內容需後續維護] → 在 changelog 內保留固定格式，並在流程中加入更新提醒。
- [頁首插入造成部分頁面視覺擁擠] → 使用一致樣式與留白，必要時允許頁面局部關閉副標。

## Migration Plan

- 新增版本常數與共用頁首 UI。
- 逐頁加入簡短說明文字。
- 新增版本更新頁與導覽入口。
- 更新版本號為 `0.1.1 beta`。
- 若需回滾：移除 `render_header()` 呼叫與 changelog 頁面，版本號退回前一版即可。
